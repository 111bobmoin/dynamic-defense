# dynamic_defense_ceni 使用说明

本文说明如何在当前 `~/dynamic-defense` 仓库中复现 `dynamic_defense_ceni` 接入流程，并在 sidecar 大屏状态页看到动态防御结果实时显示。

## 一、目录关系说明

`extensions/dynamic_defense_ceni/` 是 sidecar 适配器，负责：

- 读取 `dynamic_defense_ceni` 的 `reports/runtime`；
- 转换并写出 `dynamic_defense.json`；
- 提供 sidecar 状态页；
- 记录动作日志。

`integrated_modules/dynamic_defense_ceni/` 是 `dynamic_defense_ceni` 算法模块快照，负责：

- `attack_defender.py`；
- 特征模板；
- 策略库；
- PyTorch `family_v3` 检测模型；
- `actor_critic` 策略优化；
- REST/stateful controller 联动；
- `reports/runtime` 输出。

明确区分：`extensions` 是适配层，`integrated_modules` 是算法本体，二者不要混淆。

## 二、环境准备

当前推荐使用两个环境。

平台/sidecar 环境：在 `~/dynamic-defense` 根目录使用 venv。

```bash
cd ~/dynamic-defense
source .venv/bin/activate
python --version
```

`dynamic_defense_ceni` 算法环境：推荐使用已验证过的 `dd37`。

```bash
cd ~/dynamic-defense/integrated_modules/dynamic_defense_ceni
conda activate dd37
python --version
```

如果没有 conda，可以按 `integrated_modules/dynamic_defense_ceni/requirements.txt` 或 `integrated_modules/dynamic_defense_ceni/environment.yml` 自建环境；但当前验证口径以 `dd37` 为准。

## 三、重要代理设置

在 WSL 中访问 `127.0.0.1:18082` 时，如果设置了 `http_proxy`、`https_proxy`、`all_proxy`，可能导致 REST 请求被代理劫持，出现：

```text
HTTP/1.1 502 Bad Gateway
Proxy-Connection: keep-alive
```

因此运行 controller、`attack_defender.py`、bridge 前建议执行：

```bash
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY
export NO_PROXY=127.0.0.1,localhost
export no_proxy=127.0.0.1,localhost
```

## 五、真实运行 real-reports 模式完整复现

真实运行需要三个终端。

### 终端 1：启动 REST/stateful controller

```bash
cd ~/dynamic-defense/integrated_modules/dynamic_defense_ceni
conda activate dd37

unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY
export NO_PROXY=127.0.0.1,localhost
export no_proxy=127.0.0.1,localhost

mkdir -p runtime reports
rm -f runtime/controller_state.json
rm -f reports/controller_execution_plan.jsonl
rm -f reports/controller_translated_actions.jsonl
rm -f reports/controller_actions.jsonl

python scripts/translating_defense_controller.py \
  --host 127.0.0.1 \
  --port 18082 \
  --execution-mode stateful
```

该终端需要保持运行。

### 终端 2：运行 attack_defender.py

```bash
cd ~/dynamic-defense/integrated_modules/dynamic_defense_ceni
conda activate dd37

unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY
export NO_PROXY=127.0.0.1,localhost
export no_proxy=127.0.0.1,localhost

python attack_defender.py \
  --input data/cicids2017_subset/cicids2017_expanded_scenario_ordered.csv \
  --build-templates \
  --window-size 200 \
  --limit 2200 \
  --detector hybrid \
  --torch-threshold 0.70 \
  --optimizer actor_critic \
  --torch-model models/torch_flow_classifier_expanded_family_v3.pt \
  --torch-meta models/torch_flow_classifier_expanded_family_v3_meta.json \
  --adapter rest \
  --controller-endpoint http://127.0.0.1:18082
```

预期输出包含：

## 六、状态页展示内容解释

- 数据模式：区分当前 payload 来源，`static-demo` 表示演示载荷，`real-reports` 表示读取真实 `attack_defender.py` 和 REST/stateful controller 输出。
- 接入状态：展示动态防御状态，例如 `发现攻击 / attack_detected`。
- 风险评分：展示 bridge 转换后的 `risk_score`，real-reports 中检测到策略调整事件时为 75。
- 动态防御执行结果：展示窗口数、策略调整事件数、检测成功率、防御成功率、攻击族准确率、策略匹配准确率和执行计划行数。
- 体系策略切换可视化：展示从流量窗口输入、攻击特征提取、检测源选择、攻击族识别、策略优化到 CENI JSON 输出的流程。
- 使用模型：展示 FlowMLP `family_v3` 检测模型、meta 文件、label mode、hybrid 检测模式和 `actor_critic` 策略优化器。
- 网络拓扑风格展示：用平台已有拓扑风格展示受影响链路和节点，便于从网络视角理解动态防御结果。
- 最近动作日志：展示 sidecar bridge、status server、validator 等动作日志，用于定位读取、转换、写出和页面请求过程。

特别说明：`static-demo` 只表示演示载荷；`real-reports` 表示读取真实 `attack_defender.py` 和 REST/stateful controller 输出。

## 七、常见问题排查

### 1. 页面显示 static-demo，不是 real-reports

原因：运行了 `--static-demo`，或者没有重新 bridge 真实结果。

解决：不要加 `--static-demo`，运行：

```bash
python extensions/dynamic_defense_ceni/bridge.py \
  --ceni-project-root integrated_modules/dynamic_defense_ceni \
  --once
```

### 2. 页面显示 unknown

原因：`dynamic_defense.json` 是旧 payload，缺 `data_mode`。

解决：重新运行新版 bridge。

### 3. bridge 不生成 dynamic_defense.json

原因可能包括：

- `dynamic_defense_summary.json` 缺失；
- `dynamic_defense_events.csv` 缺失；
- `controller_state.json` 缺失；
- `controller_execution_plan.jsonl` 缺失；
- 没启动 REST/stateful controller。

解决：按 real-reports 三终端步骤重新跑。

### 4. controller 不生成 action/state 文件

原因可能包括：

- 代理劫持 `127.0.0.1`；
- `18082` 端口没监听；
- `attack_defender.py` 没重新运行。

排查：

```bash
ss -ltnp | grep 18082
curl --noproxy '*' -i http://127.0.0.1:18082/
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY
export NO_PROXY=127.0.0.1,localhost
export no_proxy=127.0.0.1,localhost
```

### 5. curl 127.0.0.1:18082 返回 502 Bad Gateway

说明请求走了代理。

解决：

```bash
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY
export NO_PROXY=127.0.0.1,localhost
export no_proxy=127.0.0.1,localhost
```

### 6. pytest 全仓库失败

说明原平台 `log/TEST_main/DLSTM` 测试存在依赖问题。

本次只验证 sidecar 相关测试：

```bash
python -m pytest -q tests/test_dynamic_defense_ceni_extension.py tests/test_dynamic_defense_ceni_status_server.py
```
